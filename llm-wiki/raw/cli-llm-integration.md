# Руководство по интеграции и работе с CLI-системами LLM

Данный документ описывает правила, архитектуру и особенности работы с локальными CLI-утилитами для вызова больших языковых моделей (LLM) — Codex, Gemini CLI и Claude CLI в рамках Harness Protocol и платформы KBPro.

## 1. Поддерживаемые CLI-системы и Модели

Набор доступных моделей определяется файлом `llm-config.json`. Все модели разделены на 4 уровня (Tiers): Frontier, Advanced, Medium, Light.

### 1.1 OpenAI Codex (`codex`)
CLI-инструмент для работы с моделями OpenAI.
- **Доступные модели**: 
  - GPT-3.5-turbo, GPT-4-turbo, GPT-4o, GPT-4o-mini
  - Серия o (o1, o1-mini, o3, o3-mini)
  - Серия 5.x (GPT-5.5, GPT-5.6 Sol, GPT-5.6 Terra, GPT-5.6 Luna)
- **Шаблон вызова**: `codex exec -m "{model_id}" -` (промпт передается через stdin)

### 1.2 Claude CLI (`claude`)
CLI-инструмент для работы с моделями Anthropic.
- **Доступные модели**:
  - Claude 3 (Haiku, Sonnet, Opus), Claude 3.5 (Haiku, Sonnet)
  - Claude 4.x/5.x (Haiku 4.5, Sonnet 4.6, Opus 4.8, Fable 5, Mythos 5)
- **Шаблон вызова**: `claude --model="{model_id}" -p "{prompt}"`

### 1.3 Antigravity CLI (`agy`)
CLI-инструмент для работы с моделями Google.
- **Доступные модели**:
  - Gemini 1.5 (Flash, Pro), Gemini 2.0 (Flash, Pro)
  - Gemini 3.1 (Flash-Lite, Pro), Gemini 3.5 (Flash, Pro)
- **Шаблон вызова**: `agy --model "{model_id}" -p "{prompt}"`

## 2. Архитектурные правила работы с CLI

### 2.1 Передача аргументов и промптов
- **Лимиты командной строки**: При вызове через Node.js (`child_process.spawn`) или PowerShell существует лимит на длину строки (около 8-32 КБ). Если промпт или системная инструкция большие, необходимо использовать потоковый ввод (`stdin`).
- Пример использования stdin для Codex:
  ```javascript
  const child = spawn('codex', ['exec', '-m', 'gpt-5.5', '-'], { shell: true });
  child.stdin.write(systemPrompt + '\n' + userPrompt);
  child.stdin.end();
  ```

### 2.2 Управление окружением и PATH
- Если CLI-утилита установлена как PowerShell-алиас или функция в профиле `$PROFILE`, стандартный `spawn` в Node.js **не найдет** её, так как он не загружает интерактивный профиль.
- Обязательно убедитесь, что путь к бинарным файлам CLI (например, `.bin` или папка с python-скриптами) добавлен в **глобальные системные переменные PATH**.

### 2.3 Обработка ошибок, stdout и stderr
- **Коды возврата (Exit Codes)**: В нормальном состоянии CLI завершается с кодом `0`. Код `1` означает ошибку парсинга, отсутствие доступа, лимит запросов или сбой самой модели.
- **stderr-шум**: Некоторые CLI (особенно Codex) выводят служебную информацию (например, "tokens used", прогресс-бары) в `stderr`. В Node.js это может вызвать ложное срабатывание ошибки. Скрипт парсера должен фильтровать технический текст от реальных результатов в `stdout`.

## 3. Распространенные ошибки и "подводные камни" (Pitfalls)

### 3.1 Ошибка "failed to load skill" (Codex)
Codex автоматически парсит файлы навыков (`SKILL.md`) из папок `~/.codex/skills/` и `.agents/skills/`. Codex **строго валидирует YAML frontmatter**:
1. **UTF-8 BOM**: Файлы не должны содержать невидимый маркер `0xEF 0xBB 0xBF`. YAML парсер Codex падает при его наличии.
2. **Отсутствие разделителей**: Метаданные обязательно должны быть обернуты в `---`.
3. **Длина строк**: Поле `description` в YAML **не может превышать 1024 символа**. При превышении Codex вернет exit code 1 на этапе инициализации и не выполнит запрос модели.

### 3.2 Лимиты и Rate Limits
LLM-провайдеры применяют жесткие квоты к бесплатным и платным аккаунтам.
- Ошибка `ERROR: You've hit your usage limit` приводит к exit code 1. 
- Движок интеграции (например, `llmClient.js` + `strategyEngine.js`) **обязан** перехватывать эти ошибки и использовать паттерн каскадирования (Cascade Fallback).

## 4. Паттерн "Опрос перед использованием" (Ping First)

Перед запуском агента или многошаговой задачи необходимо проверить доступность CLI-интерфейсов и конкретных моделей. В Harness Protocol для этого используется `ping_models.js`.
- Моделям отправляется промпт-заглушка (`ping`).
- Устанавливается жесткий таймаут (15 секунд). Если CLI завис, он отбрасывается.
- Статус (`online` / `offline`) сохраняется в `llm-config.json`.
- Модуль роутинга обязан отфильтровывать `offline` модели до попытки их вызова.
