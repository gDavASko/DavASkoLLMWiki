# Профиль структурной нарезки v4

## Правило совместимости индекса

Параметры нарезки являются частью формата индекса. После изменения профиля запуск инкрементальной индексации запрещён: требуется явный `node system/build-index.js --force`. Это не меняет embedding-модель данного репозитория и не разрешает её замену. Переход v3 → v4 меняет ТЕКСТ, уходящий в эмбеддинг (см. ниже), поэтому обязателен `--force`.

## Правила v4

- Родительский уровень — Markdown-секция и путь её заголовков.
- Поисковые чанки имеют цель 200 слов и предел 300 слов.
- Короткие законченные секции, таблицы, списки и fenced code blocks не склеиваются и не режутся ради искусственного размера.
- Длинный абзац режется сначала по предложениям. Контекстное перекрытие **назад** 32 слова добавляется на каждой границе retrieval-чанка после первого: хвост предыдущего фрагмента сохраняет определения и связи при переходе через абзацы, списки, таблицы и заголовки. У первого чанка overlap назад равен нулю.
- **Overlap ВПЕРЁД (v4, `chunk_forward_overlap_words`, по умолчанию 32).** К каждому чанку, кроме последнего, приписывается **голова следующего фрагмента** под меткой `[Контекст следующего фрагмента]`. Симметрично overlap назад: чанк «видит», чем продолжается мысль. Добавляется пост-проходом и не резервирует бюджет упаковки — это служебный контекст для эмбеддинга, `contentWords` (исходное содержимое) остаётся в пределах `max`. Поле `forwardWords` пишется в метаданные чанка.
- **Иерархия документа в эмбеддинге (v4).** Секции документа нередко лежат отдельными файлами, а имя сущности (напр. таб «Робот гуманоид») хранится только во фронтматтере (`parent_tab`/`tab_name`), не в теле секции. Без него секция «Концепция»/«Анимации» векторизуется без имени сущности и слабо матчит запрос про неё; при этом относительный порог поиска (`relative_alpha`) при одном точном попадании (Overview) поднимается так высоко, что отсекает остальные секции — выдача схлопывается до одного огрызка. Поэтому к тексту КАЖДОГО чанка **при эмбеддинге** приписывается путь `[parent_tab > tab_name]`. Меняется только текст для эмбеддинга; сохранённый `chunk.text`, отображение и цитаты не затрагиваются. Крошка входит в MD5-контроль, поэтому смена `tab_name` триггерит переэмбеддинг.
- В LanceDB записываются `parentId`, путь секции, индексы соседей, размер и тип границы.

## Проверка

```bash
node system/scripts/audit-chunks.js
```

Команда ничего не меняет и показывает покрытие корпуса, долю одночанковых документов, forced boundaries и overlap.

## Слои и инкрементальная индексация

- Индексатор принимает слой с `wiki.json`, если существует хотя бы один из каталогов `wiki/` или `raw/`. Raw-only слой является допустимым: Git не сохраняет пустую папку `wiki/`.
- Обычная команда `node system/build-index.js` индексирует только добавленные, изменённые или удалённые документы. `--force` используется только при намеренной полной пересборке — после изменения профиля либо для миграции legacy-индекса.
- Профиль v3 является частью формата индекса. Его изменение без `--force` запрещено, чтобы в LanceDB не смешивались чанки, созданные разными алгоритмами.
